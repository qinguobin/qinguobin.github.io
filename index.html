一次只成功了一半的尝试：把企业微信消息钉到桌面

发表于 2026-10-17

这是我的第二篇博文。上一篇教大家搭了自己的博客，这一篇记一次不太成功的尝试： 想把企业微信里需要你处理的消息自动钉到桌面最上层，处理完一键勾掉， 顺带把企微里的未读红点也消掉——最后只做成了一半，而且有个绕不过去的硬条件： 企微窗口必须真实显示在屏幕上。我最初"任何时候只要登录就能读到"的目标，并没有达到。

丑话说在前面，这篇不包装成成功学：企业微信的聊天记录，官方不让你读。 我把哪几条路走不通、哪条路能走通、边界在哪里，全部用实测讲清楚。 你照着做，半天能跑起来；看完更能少撞几天墙——以及提前知道哪些事做不到。

篇幅有点长，分为九步。

第一步：先摸清企微的底，再决定怎么做

需求一句话：企微收到消息 → 判断要不要你处理 → 钉在桌面。听起来不难， 但我动工前先把四条读取通道全验证了一遍，三条是死的：

通道 结论 证据
客户端 UI 自动化（UIA） ❌ 死路 企微是 Flutter 渲染，主窗口 WeWorkWindow 下只有一个 FLUTTERVIEW，UIA 只能读到 2 个空节点
官方连接器 wecom-cli ❌ 死路 chat messages list 一律返回 errcode 853006「企业未开通会话存档」
Windows 系统通知 ❌ 死路 通知探针跑了 240 秒，企微一条通知都没弹
屏幕截图 + OCR ⚠️ 唯一走通 见第四步

两个关键推理，帮你少走弯路：

  • 853006 不是授权问题。我用 4 个 chat-id 试，其中 3 个是瞎编的（wmXXXX / test）， 全部返回同一个错误码——说明拦截发生在校验 ID 之前，是企业层级的功能开关。 所以别再去点授权了，授权解决不了。

  • 企微虽然不暴露控件树，但它最终要把像素画到窗口上——像素是绕不过去的。 这就是 OCR 路线能成立的根因。

顺带回答一个高频问题：个人微信更读不到。微信官方压根没有 "读取个人聊天记录"的 API（只开放公众号 / 小程序 / 企业微信三类）， 本地 12 个数据库又全部是 SQLCipher 加密。不是权限问题，是这个能力不存在。

第四步：屏幕捕获——全项目最核心的一段

原理：Flutter 不暴露控件树，但像素总要画到窗口上，所以截图 + OCR。 三个必须踩对的点，每个都对应一个"毫无反应"级别的坑：

1. 用 PrintWindow，不要用 BitBlt

企微走 DirectComposition 合成，BitBlt 只能拿到过期的那一帧—— 这就是"用户明明发了消息，程序却毫无反应"的真凶。

2. OCR 之前先放大 2 倍

Windows OCR 对 12px 小字识别率很差。用 GDI HALFTONE 模式高质量放大 2 倍后 才可用（人名偶有误差，消息正文基本准确）：

3. 强制把 alpha 通道填成不透明

窗口截图的 alpha 是 0，OCR 引擎会当成全透明图，直接返回 0 行：

找到"会话列表"那一列

从整窗 OCR 结果里按 x 坐标区间切出列表列（默认 x ∈ [0.15, 0.38]）， 再按 y 排序。还要确认企微停在**「消息」页**——靠列表右侧的 时间戳特征（刚刚 / N分钟前 / 昨天 / HH:MM）判断， 切到工作台/文档页自动跳过（否则会把"审批""打卡"当成消息）。

OCR 错字怎么办

@秦国彬 会被识别成 @泰国彬 / @孬王彬，精确匹配全漏。 用 difflib 做相似度模糊匹配；代价是群名也可能误匹配， 所以保留一个 group_senders 白名单兜底。

第五步：判断"这条消息要不要你处理"

三条规则，都是被真实消息教育出来的：

  1. 群消息只收 @你本人的。@所有人 / @全体成员 一律不算—— 群里 @所有人 大多是公告，钉上去只会干扰你。

  2. 先扫否定词。"公司年会照片已上传，无需回复"这种， 命中"回复"俩字会被误判成待办；所以先扫 无需 / 不用 / 不必 / 已通过， 命中直接判为无需处理。

  3. AI 判断 + 关键词兜底。共用任意 OpenAI 兼容接口 （DeepSeek / 通义 / Kimi / Ollama 都行），输出"要不要处理 + 优先级 + 一句话理由"， 理由直接显示在卡片上。不配 key 也能跑，自动降级为关键词规则。

第六步：做一块常驻桌面的小组件

用 tkinter，无边框 + 置顶 + 可拖动 + 可滚动。交互上是用户骂出来的：

  • 一会话一张卡：同一个联系人/群的多条消息合并成一卡， 卡内按时间从上到下排，不分框。

  • 两级勾掉：行首 ☐ 勾掉单条；卡片头 ☐ 勾掉整个会话。

  • 收起只留标题条：单击标题条展开（别学我第一版绑了双击，用户以为点不动）。
  • 收起状态不保存窗口尺寸（否则重启后只剩一条 34px 的标题栏，内容全没）。

第七步：勾掉的同时，消掉企微里的角标

企微没有开放"标记已读"的接口，Flutter 下 UIA 也点不动会话。 实测可用的主路线是快捷键：

Ctrl+F 这条我实测确认能唤起企微搜索框。如果某台机器上不灵：

  • 先跑 tools/test_hotkey.py k 试试 Ctrl+K，好用就把配置里 mark_read.search_key 改成 "k"；

  • 或者直接鼠标点搜索框：设 mark_read.click_search_offset = [160, 24]。

注意一个产品细节：在企微里先读了消息，桌面上的固定内容不会被移除。 桌面卡片只认你手动勾掉——这是刻意设计的，避免"看了一眼企微，待办就丢了"。

第八步：让它跟着企业微信自动启停

一个看门狗脚本监听 WXWork.exe 进程：企微打开 → 自动拉起程序； 企微关闭 → 自动退出（待办已存盘，不丢）。

再加开机自启：在系统启动项放一个几 KB 的 vbs 入口， 登录后静默常驻。但有一点必须说清：程序得由你双击 Start.bat 启动， 或者等下次开机自动起来——从终端/自动化环境里拉起的进程会被系统回收， Start-Process、wscript、schtasks 全试过，都活不下来。

第九步：最值得记住的几个坑

34 个坑里挑最狠的 8 个，每个都够你查半天：

  1. 64 位 ctypes 不设 restype，句柄被截断。GetClipboardData 返回的 64 位句柄被当成 32 位 c_int，剪贴板永远读成空字符串—— 我因此一度误判"Ctrl+F 唤起搜索失败"，其实快捷键一直是好的。 教训：64 位 Windows 上，任何返回指针/句柄的 Win32 函数都必须显式设 restype。

  2. BitBlt 抓 Flutter 窗口只能拿到过期帧（见第四步第 1 点）。

  3. 最小化 = 画面冻结。受控实验：用户发消息后盯 70 秒，画面指纹纹丝不动； 移到屏幕外也一样，移回屏幕内立刻恢复。企微最小化时停止渲染， 这是操作系统 + Flutter 的硬行为，绕不过去。

  4. GetWindowRect 在最小化时不一定是 (-32000, -32000)—— 微信最小化返回的是 314x50 的小矩形。所以要用 IsIconic() 判断， 再用 GetWindowPlacement 拿还原矩形。

  5. 企微有多个标题都叫"企业微信"的窗口，不判断当前停在哪一页， 就会把工作台的"审批""打卡"当成消息，生成一堆垃圾待办。

  6. @所有人 被当成 @我（见第五步）。

  7. "无需回复"被误判成待办（见第五步）。
  8. 改了代码但进程里跑的是旧版本——删掉 __pycache__ 再重启， 别对着旧代码debug半天。

最后：成果与边界

做到了的（企微窗口可见时全自动）：

  • 打开企微自动弹出小组件，关掉自动退出
  • 自动捕获新消息 → AI 判断 → 钉到桌面 → 一键勾掉 → 顺带清角标
  • 一会话一卡、按时间排、两级勾掉、群消息只收 @我

做不到的（客观限制，不是代码问题）：

  • 企微最小化 / 移出屏幕 / 停在工作台页时读不到 （想眼不见为净，就用别的窗口盖住它，或扔到另一个虚拟桌面——这两种都照读不误）

  • 用官方接口读聊天记录（企业未开通「会话内容存档」）

  • 读个人微信消息（官方无此 API）

唯一能根治"只要登录就一定读到"的路：让企业管理员开通 「会话内容存档」（付费功能）。开通后服务端直接拿聊天记录， 跟窗口状态完全无关。读取模块我已经写好备着了，企业一开通即用。

教你如何手把手搭建自己的hexo（保姆级教程）

发表于 2020-05-11 更新于 2020-05-12

这是我的第一篇博文，在成功搭载了自己的博客之后，我发现博客搭建并不像安装注册软件这么简单，尤其是本地与云端之间的链接尤为繁多，小白容易遇难而退，所以我针对这种现象，把我搭载博客的方法精简再精简传授给你们，内容其实很简单，分为七个步骤

第一步：node安装

下载地址 node

进入官网，下载稳定版本，

打开运行，一路next，
win＋R调出命令窗口，打开cmd，

输入node -v,窗口显示版本号

第二步：github注册

打开guithub官网。

Username输入用户名（不能重复，类似于游戏ID），邮箱和密码，点击注册。

进入Welcome to GitHub界面，随便选，提交。

打开邮箱，点击邮箱。

start a project,Repository name方框里输入 用户名.github.io,一定要以这种形式，然后提交

第三步：git for win安装

下载地址git

进入官网，点击下载

打开安装，一路next
win＋R调出命令窗口，打开cmd，

输入git，会跳出版本号

第四步：github HSS配置

在git安装路径下找到git-bash.exe,打开输入命令 ssh-keygen -t rsa -C “自己的邮箱”，一直回车，直到得到反应如下
))
打开github，右上角头像-settings-SSH and GPG keys，title填用户名
)
在安装目录中找到id_rsa.pub文件，用记事本打开，代码全选复制，粘贴入key,提交
)

第五步：hexo本地使用

百度hexo,复制蓝框里的安装命令

在你想安装的磁盘里创建文件夹blog,打开gitcmd cd到blog文件夹，粘贴安装命令，回车

输入 hexo init 你的博客名 回车（只有hexo和init和你的博客名之间有两个空格键）

cd博客目录，输入命令npm install,回车

安装结束，输入hexo s -p 5555命令，反馈网址，粘贴网址至浏览器查看

第六步：sublime安装

下载地址sublime

进入官网，点击下载

在安装目录中找到sublime_text.exe,打开
打开文件系统，直接将博客目录拖进sublime
显示应该是这样
