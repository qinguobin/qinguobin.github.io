手把手教你在车机上装 DiPlay（保姆级教程）

发表于 2026-10-24

这是我的第三篇博文。上一篇记录了把企业微信消息钉到桌面的失败尝试，这一篇来点实用的：给安卓车机装上 CarPlay。

说白了就是两件事。一是 DiPlay，一个开源的 CarPlay 接收器，装在车机上，iPhone 就能投屏过来；二是 LANDrop，一个局域网传文件的工具，负责把 DiPlay 的安装包送进车机。

为什么传个文件还要专门动用 LANDrop？因为车机这东西很尴尬：一般没有应用商店，插电脑也不一定认，开发者选项更是不知道藏在哪。折腾一圈你会发现，车机上唯一现成的下载通道就是它自带的浏览器。所以整个思路是：先用车机浏览器把 LANDrop 下下来装好，再让手机和车机连同一个网，用 LANDrop 把安装包传过去，最后在车机上安装调试。

开始之前先交代两句。DiPlay 目前主要面向比亚迪的安卓车机（DiLink），其他品牌官方明说不保证能用；它还不是苹果认证的产品，属于社区公开预览版，iOS 一更新就有可能失效。想清楚了再往下看。

先认识一下两个主角

DiPlay，GitHub 项目地址是 https://github.com/shihabal3amri/DiPlay ，最新版本 v0.2.21（2026 年 10 月 17 日发布的公开预览），安装包 DiPlay-0.2.21.apk，18 兆左右，要求安卓 7.0 以上。它不需要越狱、不需要买投屏盒子、不需要注册账号，USB 有线和无线都能连。无线支持三种方式：车载热点（默认推荐）、Wi-Fi Direct、已有 Wi-Fi 同一局域网。

LANDrop，官网 https://landrop.app ，同样是开源项目，可以理解成跨平台的 AirDrop：同一局域网里的设备自动互相发现，点一下就传文件，不要数据线、不要账号、不走流量。它有 iOS、安卓、Windows、macOS、Linux 全平台的版本，我们用安卓版装车机，手机或电脑版当发送端。界面长这样（官方截图，iOS 版，安卓版布局类似）：

第一步：用车机浏览器下载 LANDrop

车机连上网（车流量卡、手机热点都行），打开车机自带的浏览器，地址栏直接输入下面这个官方直链，回车就能下载：

https://releases.landrop.app/landrop-v2-flutter/LANDrop-flutter-latest-android.apk

下载完在通知栏或浏览器的下载管理里点开，直接安装。如果车机提示"禁止安装未知来源应用"，去设置的安装权限里允许一下，装完可以再关回去。

顺手把你手机（或电脑）上也装一份 LANDrop，后面要用它发包。电脑版下载地址：https://releases.landrop.app/landrop-v2-qt/LANDrop-latest-win.zip ，手机版可以在 LANDrop 官网扫码，或者直接用上面的安卓直链。

第二步：让车机和手机在同一个局域网

LANDrop 靠局域网自动发现设备，所以两边必须在同一个网里。最省事的做法是开手机热点，让车机连上来；反过来用车机自带的热点、手机连上去也可以。没有网也不要紧，LANDrop 官网特意说了，热点环境下传文件不消耗流量。

连好之后，车机和手机都把 LANDrop 打开，稍微等几秒，主界面里应该就能看到对方的设备名。能看到，第二步就算过关了。

第三步：在你手机上下载 DiPlay 安装包

用手机浏览器打开 DiPlay 的发布页：

https://github.com/shihabal3amri/DiPlay/releases

最新的是 v0.2.21，把里面的 DiPlay-0.2.21.apk 下载下来（约 18MB）。懒得翻的话，直链在这里：

https://github.com/shihabal3amri/DiPlay/releases/download/v0.2.21/DiPlay-0.2.21.apk

注意认准官方发布页，别从第三方下载站拿包。介意安全的话，发布页里还有个 SHA256SUMS.txt，可以校验一下文件完整性。

第四步：用 LANDrop 把安装包传到车机

手机上打开 LANDrop，选中刚下载的 DiPlay-0.2.21.apk，发送目标是车机上的 LANDrop；车机端会弹出一个接受确认，点一下同意，文件就开始传了。18 兆的包在局域网里几秒钟的事，传完一般落在车机的 Download（下载）目录里，车机的文件管理器能找到。

第五步：在车机上安装

用车机文件管理器找到 APK，点开安装。几个注意事项官方文档里都写明了，我挑要紧的说：

一是装在车机上，不是 iPhone 上，这是最容易犯迷糊的地方。二是要求安卓 7.0 以上，7.0 到 8.1 这一段官方说还没在实车上充分验证，装不装自己掂量。三是装之前把其他投屏类应用关掉，DiPlay 可以和原车的 DiAuto 共存，但连接时一次只能跑一个投影应用。四是以后升级尽量直接覆盖安装，不要卸载重装，覆盖能保留设置和配对记录；不同签名的包之间也不能互相覆盖升级。

第六步：连接 iPhone

装好打开后，会看到这样的主界面（官方截图）：

第一次会要权限：蓝牙（附近设备）、Wi-Fi 和定位（老版本安卓要）、麦克风（Siri 和通话用）、通知。用到哪个给哪个。

有线连接最简单也最稳：iPhone 插车机的 USB 口，必须是数据口加数据线，纯充电口和充电线是不行的；然后在 DiPlay 里选 USB 连接，iPhone 上点信任。如果插上以后每隔几秒就掉线重连，去 设置、连接、USB 连接、iPhone 充电，把它调成"降低"或"低"，让 iPhone 充电慢一点换稳定。

无线连接默认走车载热点：在 设置、连接、连接设置、车载热点 里保存热点名和密码，热点尽量开 5GHz；iPhone 保持蓝牙和 Wi-Fi 开着，并和车机完成蓝牙配对，然后点连接手机。配对正常的固件上，蓝牙握手会自动把热点信息给 iPhone，不用手动连。另外两种方式（Wi-Fi Direct、已有 Wi-Fi 同一局域网）在同一个连接设置里，走路由器的话记得把路由器的 AP 隔离关掉。

第七步：调优和排错

画面先按官方给的保守参数来：帧率 30，图标文字用默认，"高效视频 HEVC"先关着；车机性能弱、画面卡，再把分辨率降到 80% 或 60%。这些都在设置页里（官方截图），改了分辨率和帧率要点"应用并重连"才生效，光选上是没用的：

CarPlay 界面里按住下滑（默认三根手指）能呼出快捷菜单。

出了问题，DiPlay 自带诊断：设置、诊断、保存诊断报告，安卓 10 以上存在 Downloads/DiPlay 目录，老版本会申请存储权限，报告是个 txt。排查卡顿可以打开同一个页面里的 FPS 计数器，能直接看到帧率和解码耗时。无线怎么都连不上、或者重装后连不上，试试 设置、连接、无线连接帮助、重置 CarPlay Wi-Fi。CarPlay 画面四角透出车机壁纸的话，在 CarPlay 的设置菜单里选 Safe area、黑色圆角，把半径调到刚好盖住为止。

要反馈问题就去 GitHub 提 issue，带上车型、固件和安卓版本、iPhone 的 iOS 版本、连接方式，但热点密码千万不要带上去。

最后说两句

这套东西的本质，是社区从公开固件里还原出来的 CarPlay 接入能力，不是苹果官方认可的方案。能不能跑、稳不稳，很看车型、车机系统和 iOS 版本的组合，官方文档里给的都是"在某某实车上验证过"这种很具体的说法，而不是打包票。我的看法是：能跑起来就是赚了，跑不起来也当学了一圈车机安卓的玩法。祝折腾顺利。

一次只成功了一半的尝试：把企业微信消息钉到桌面

发表于 2026-10-17

这是我的第二篇博文。上一篇教大家搭了自己的博客，这一篇我想说说我折腾企业微信的一件事：把企微里需要我处理的消息自动钉到桌面最上面，处理完一键勾掉，顺便把企微里的未读红点也消了。

先说结果吧，省得你抱太大期望：最后只做成了一半。有个绕不过去的硬条件是企微窗口得真真实实摆在屏幕上。我一开始想的"只要企微登录着，不管它在干嘛都能读到消息"这个目标，没达到。所以这篇不算是成功教程，更多是我踩了一堆坑之后，把哪些路走得通、哪些走不通讲清楚，你照着弄能少撞几天墙。

说白了，企业微信的聊天记录，官方压根不让你读。下面把这件事从头到尾说一遍。

第一步：先把企微摸清楚，再动手

需求其实一句话：企微来消息了 → 判断一下要不要我处理 → 钉到桌面上。听起来挺简单，但我真动手之前，先把能读的四条路都试了一遍，结果三条都是死路。

第一条，用客户端自带的界面自动化（UIA）。不行。企微整个界面是用 Flutter 画的，主窗口底下就一个 FLUTTERVIEW，界面自动化只能读到两个空节点，啥也抓不到。

第二条，走官方连接器 wecom-cli 去读消息。也不行。不管我怎么试，它都回一个 errcode 853006，意思是"你们公司没开会话存档"。我当时还不死心，换了四个不同的会话 id 去试，其中三个是我瞎编的，结果还是一个错。这就说明，拦截发生在校验 id 之前，是公司层面的开关，不是你授权不授权的问题。所以别再去点授权了，点了也没用。

第三条，等 Windows 的系统通知。还是不行。我专门写了个探针挂在那跑，等了四分钟，企微一条通知都没弹出来。

第四条，屏幕截图加 OCR 识别。这条总算走通了，后面细说。

为什么前三条都不行、就最后这条行？因为企微虽然不把界面结构（控件树）露出来，但它最后总得把字和图一笔一笔画到窗口上。画出来的像素是躲不掉的，截图加识别就是从这上面想办法。

顺带说一句，有人问我个人微信能不能也读。更不行。微信官方压根没开放"读个人聊天记录"的接口，只开放了公众号、小程序、企业微信这三类。本地的数据库倒是有一堆，可全是加密的，打不开。所以这不是权限问题，是压根没这功能。

第四步：屏幕捕获，这是整个项目最关键的地方

原理刚才说了，企微不露控件树，但像素要画出来，所以截图加 OCR。这一块有三个坑，每个都能让你卡到"毫无反应"。

1. 用 PrintWindow，别用 BitBlt

企微的界面是 DirectComposition 合成的，BitBlt 截出来的永远是过期的那一帧——你明明发了消息，程序却跟没看见一样，根因就在这。

2. OCR 之前先把图放大两倍

Windows 自带的 OCR 对十二像素的小字识别率很差，用 GDI 的 HALFTONE 模式高质量放大两倍之后才靠谱。人名字偶尔会认错，正文基本准：

3. 把透明通道强制填成不透明

窗口截图出来的图，透明通道是 0，OCR 引擎会把它当成一张全透明的图，直接返回空。所以得手动填上：

找到"会话列表"那一列

从整张图的识别结果里，按 x 坐标的区间把左边那一列切出来，再按 y 排好（默认区间在 x 的 0.15 到 0.38 之间）。还得确认企微现在停在"消息"页，靠列表右边的时间戳（"刚刚""几分钟前""昨天""几点几分"这种）来判断。要是它停在工作台或者文档页，就跳过，不然会把"审批""打卡"这种当成消息。

OCR 认错字怎么办

比如"@秦国彬"会被认成"@泰国彬"或者"@孬王彬"，精确匹配全漏。我用 difflib 做相似度模糊匹配，代价是群名也可能误匹配，所以又留了个白名单兜底。

第五步：判断这条消息要不要我处理

这块三条规则，都是被真实的消息教训出来的。

一是群消息只收 @我本人的。@所有人、@全体成员一律不算，因为群里 @全体大多是公告，钉上去反而烦你。

二是先扫否定词。像"公司年会照片已上传，无需回复"这种，光看"回复"俩字会被误判成待办，所以先扫"无需、不用、不必、已通过"，命中了就直接判成不用处理。

三是 AI 判断加关键词兜底。用的是任意 OpenAI 兼容的接口，DeepSeek、通义、Kimi、Ollama 都行，让它输出"要不要处理、优先级、一句话理由"，理由直接显示在卡片上。你不配 key 也能跑，会自动降级成关键词规则。

第六步：做一块常驻桌面的小组件

用 tkinter，无边框、置顶、可拖动、可滚动。这里的好几个交互都是被用户骂出来的。

同一个联系人或者群的多条消息，合并成一张卡片，卡里按时间从上往下排，不分框。每张卡有两级勾掉：行首的小方框勾掉单条，卡片头的勾掉整个会话。收起的时候只留标题条，单击标题条就展开——别学我第一版绑成了双击，用户还以为点不动。还有，收起状态不要保存窗口尺寸，不然重启之后只剩一条三十四像素的标题栏，内容全没了。

第七步：勾掉的同时，把企微里的角标消掉

企微没有开放"标为已读"的接口，Flutter 下面界面自动化也点不动会话。我实测下来，能走通的主路线是快捷键：

Ctrl+F 这条我实测能唤起企微的搜索框。万一你那台机器不灵，可以先跑 tools/test_hotkey.py k 试试 Ctrl+K，好使就把配置里的 mark_read.search_key 改成 "k"；或者直接鼠标点搜索框，设个 mark_read.click_search_offset = [160, 24]。

有个细节得说清楚：你在企微里先把消息读了，桌面上钉着的内容不会被移除。桌面卡片只认你手动勾掉——这是我故意这么设计的，免得你只是在企微里扫了一眼，待办就没了。

第八步：让它跟着企微自动启停

写了个看门狗脚本盯着 WXWork.exe 这个进程：企微打开，它就自动把程序拉起来；企微关了，它自己退出，待办都存着盘，不丢。

再加个开机自启，在系统启动项里放一个几 KB 的 vbs 入口，登录之后静默常驻。不过有一点必须说清楚：程序得由你双击那个 Start.bat 启动，或者等下次开机自己起来。从终端或者自动化环境里拉起来的进程，会被系统收走，Start-Process、wscript、schtasks 我都试过，都活不下来。

第九步：几个最值得记住的坑

前面说的那些之外，还有几个坑我印象特别深，每个都够你查半天。

一是 64 位下用 ctypes 不显式设返回类型，句柄会被截断。GetClipboardData 返回的 64 位句柄被当成 32 位的整数，剪贴板永远读出来是空字符串——我一度还误判成 Ctrl+F 唤起搜索失败了，其实快捷键一直好好的。教训就是，64 位 Windows 上，任何返回指针或者句柄的 Win32 函数，都得显式设好返回类型。

二是 BitBlt 截 Flutter 窗口只能拿到过期帧，这个前面第四步说了。

三是最小化等于画面冻住。我专门做了个对照实验，发消息之后盯着看了七十秒，画面指纹一动不动；把窗口挪出屏幕也一样，挪回来才立刻恢复。企微最小化的时候就不渲染了，这是操作系统加 Flutter 的硬行为，绕不过去。

四是 GetWindowRect 在最小化的时候不一定是负三万两千那样的坐标，微信最小化返回的是 314 乘 50 的小矩形。所以要用 IsIconic 判断，再用 GetWindowPlacement 拿还原矩形的位置。

五是企微有好几个标题都叫"企业微信"的窗口，不判断现在停在哪一页，就会把工作台的"审批""打卡"当成消息，生成一堆垃圾待办。

六是 @所有人被当成 @我，这个第五步说了。

七是"无需回复"被误判成待办，也是第五步的事。

八是改了代码，结果进程里跑的还是旧版本——把 pycache 删了再重启，别对着旧代码调半天。

最后：做到的和没做到的

做到的部分（前提是企微窗口得看得见）：

  • 打开企微，小组件自动弹出来；关掉，它自动退。
  • 自动抓新消息，AI 判断，钉到桌面，一键勾掉，顺便清掉角标。
  • 一个会话一张卡，按时间排，两级勾掉，群消息只收 @我的。

没做到的（这些是客观限制，不是代码问题）：

  • 企微最小化、挪出屏幕、或者停在工作台页的时候，读不到。你要是想眼不见为净，用别的窗口盖住它，或者扔到另一个虚拟桌面，这两种它照样读。
  • 用官方接口读聊天记录（公司没开会话内容存档）。
  • 读个人微信消息（官方没这接口）。

唯一能根治"只要登录就能读到"这条路，是让你们公司管理员去开通"会话内容存档"，这是个付费功能。开通之后服务端直接拿聊天记录，跟窗口状态完全没关系。读取的模块我已经提前写好了，公司一开通就能用。

教你如何手把手搭建自己的hexo（保姆级教程）

发表于 2020-05-11 更新于 2020-05-12

这是我的第一篇博文，在成功搭载了自己的博客之后，我发现博客搭建并不像安装注册软件这么简单，尤其是本地与云端之间的链接尤为繁多，小白容易遇难而退，所以我针对这种现象，把我搭载博客的方法精简再精简传授给你们，内容其实很简单，分为七个步骤

第一步：node安装

下载地址 node

进入官网，下载稳定版本，

打开运行，一路next，
win＋R调出命令窗口，打开cmd，

输入node -v,窗口显示版本号

第二步：github注册

打开guithub官网。

Username输入用户名（不能重复，类似于游戏ID），邮箱和密码，点击注册。

进入Welcome to GitHub界面，随便选，提交。

打开邮箱，点击邮箱。

start a project,Repository name方框里输入 用户名.github.io,一定要以这种形式，然后提交

第三步：git for win安装

下载地址git

进入官网，点击下载

打开安装，一路next
win＋R调出命令窗口，打开cmd，

输入git，会跳出版本号

第四步：github HSS配置

在git安装路径下找到git-bash.exe,打开输入命令 ssh-keygen -t rsa -C “自己的邮箱”，一直回车，直到得到反应如下
))
打开github，右上角头像-settings-SSH and GPG keys，title填用户名
)
在安装目录中找到id_rsa.pub文件，用记事本打开，代码全选复制，粘贴入key,提交
)

第五步：hexo本地使用

百度hexo,复制蓝框里的安装命令

在你想安装的磁盘里创建文件夹blog,打开gitcmd cd到blog文件夹，粘贴安装命令，回车

输入 hexo init 你的博客名 回车（只有hexo和init和你的博客名之间有两个空格键）

cd博客目录，输入命令npm install,回车

安装结束，输入hexo s -p 5555命令，反馈网址，粘贴网址至浏览器查看

第六步：sublime安装

下载地址sublime

进入官网，点击下载

在安装目录中找到sublime_text.exe,打开
打开文件系统，直接将博客目录拖进sublime
显示应该是这样

第七步：hexo发布至github
