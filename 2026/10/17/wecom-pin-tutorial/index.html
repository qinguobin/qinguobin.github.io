一次只成功了一半的尝试：把企业微信消息钉到桌面

发表于 2026-10-17 更新于 2026-10-17

这是我的第二篇博文。上一篇教大家搭了自己的博客，这一篇我想说说我折腾企业微信的一件事：把企微里需要我处理的消息自动钉到桌面最上面，处理完一键勾掉，顺便把企微里的未读红点也消了。

先说结果吧，省得你抱太大期望：最后只做成了一半。有个绕不过去的硬条件是企微窗口得真真实实摆在屏幕上。我一开始想的"只要企微登录着，不管它在干嘛都能读到消息"这个目标，没达到。所以这篇不算是成功教程，更多是我踩了一堆坑之后，把哪些路走得通、哪些走不通讲清楚，你照着弄能少撞几天墙。

说白了，企业微信的聊天记录，官方压根不让你读。下面把这件事从头到尾说一遍。

第一步：先把企微摸清楚，再动手

需求其实一句话：企微来消息了 → 判断一下要不要我处理 → 钉到桌面上。听起来挺简单，但我真动手之前，先把能读的四条路都试了一遍，结果三条都是死路。

第一条，用客户端自带的界面自动化（UIA）。不行。企微整个界面是用 Flutter 画的，主窗口底下就一个 FLUTTERVIEW，界面自动化只能读到两个空节点，啥也抓不到。

第二条，走官方连接器 wecom-cli 去读消息。也不行。不管我怎么试，它都回一个 errcode 853006，意思是"你们公司没开会话存档"。我当时还不死心，换了四个不同的会话 id 去试，其中三个是我瞎编的，结果还是一个错。这就说明，拦截发生在校验 id 之前，是公司层面的开关，不是你授权不授权的问题。所以别再去点授权了，点了也没用。

第三条，等 Windows 的系统通知。还是不行。我专门写了个探针挂在那跑，等了四分钟，企微一条通知都没弹出来。

第四条，屏幕截图加 OCR 识别。这条总算走通了，后面细说。

为什么前三条都不行、就最后这条行？因为企微虽然不把界面结构（控件树）露出来，但它最后总得把字和图一笔一笔画到窗口上。画出来的像素是躲不掉的，截图加识别就是从这上面想办法。

顺带说一句，有人问我个人微信能不能也读。更不行。微信官方压根没开放"读个人聊天记录"的接口，只开放了公众号、小程序、企业微信这三类。本地的数据库倒是有一堆，可全是加密的，打不开。所以这不是权限问题，是压根没这功能。

第四步：屏幕捕获，这是整个项目最关键的地方

原理刚才说了，企微不露控件树，但像素要画出来，所以截图加 OCR。这一块有三个坑，每个都能让你卡到"毫无反应"。

1. 用 PrintWindow，别用 BitBlt

企微的界面是 DirectComposition 合成的，BitBlt 截出来的永远是过期的那一帧——你明明发了消息，程序却跟没看见一样，根因就在这。

2. OCR 之前先把图放大两倍

Windows 自带的 OCR 对十二像素的小字识别率很差，用 GDI 的 HALFTONE 模式高质量放大两倍之后才靠谱。人名字偶尔会认错，正文基本准：

3. 把透明通道强制填成不透明

窗口截图出来的图，透明通道是 0，OCR 引擎会把它当成一张全透明的图，直接返回空。所以得手动填上：

找到"会话列表"那一列

从整张图的识别结果里，按 x 坐标的区间把左边那一列切出来，再按 y 排好（默认区间在 x 的 0.15 到 0.38 之间）。还得确认企微现在停在"消息"页，靠列表右边的时间戳（"刚刚""几分钟前""昨天""几点几分"这种）来判断。要是它停在工作台或者文档页，就跳过，不然会把"审批""打卡"这种当成消息。

OCR 认错字怎么办

比如"@秦国彬"会被认成"@泰国彬"或者"@孬王彬"，精确匹配全漏。我用 difflib 做相似度模糊匹配，代价是群名也可能误匹配，所以又留了个白名单兜底。

第五步：判断这条消息要不要我处理

这块三条规则，都是被真实的消息教训出来的。

一是群消息只收 @我本人的。@所有人、@全体成员一律不算，因为群里 @全体大多是公告，钉上去反而烦你。

二是先扫否定词。像"公司年会照片已上传，无需回复"这种，光看"回复"俩字会被误判成待办，所以先扫"无需、不用、不必、已通过"，命中了就直接判成不用处理。

三是 AI 判断加关键词兜底。用的是任意 OpenAI 兼容的接口，DeepSeek、通义、Kimi、Ollama 都行，让它输出"要不要处理、优先级、一句话理由"，理由直接显示在卡片上。你不配 key 也能跑，会自动降级成关键词规则。

第六步：做一块常驻桌面的小组件

用 tkinter，无边框、置顶、可拖动、可滚动。这里的好几个交互都是被用户骂出来的。

同一个联系人或者群的多条消息，合并成一张卡片，卡里按时间从上往下排，不分框。每张卡有两级勾掉：行首的小方框勾掉单条，卡片头的勾掉整个会话。收起的时候只留标题条，单击标题条就展开——别学我第一版绑成了双击，用户还以为点不动。还有，收起状态不要保存窗口尺寸，不然重启之后只剩一条三十四像素的标题栏，内容全没了。

第七步：勾掉的同时，把企微里的角标消掉

企微没有开放"标为已读"的接口，Flutter 下面界面自动化也点不动会话。我实测下来，能走通的主路线是快捷键：

Ctrl+F 这条我实测能唤起企微的搜索框。万一你那台机器不灵，可以先跑 tools/test_hotkey.py k 试试 Ctrl+K，好使就把配置里的 mark_read.search_key 改成 "k"；或者直接鼠标点搜索框，设个 mark_read.click_search_offset = [160, 24]。

有个细节得说清楚：你在企微里先把消息读了，桌面上钉着的内容不会被移除。桌面卡片只认你手动勾掉——这是我故意这么设计的，免得你只是在企微里扫了一眼，待办就没了。

第八步：让它跟着企微自动启停

写了个看门狗脚本盯着 WXWork.exe 这个进程：企微打开，它就自动把程序拉起来；企微关了，它自己退出，待办都存着盘，不丢。

再加个开机自启，在系统启动项里放一个几 KB 的 vbs 入口，登录之后静默常驻。不过有一点必须说清楚：程序得由你双击那个 Start.bat 启动，或者等下次开机自己起来。从终端或者自动化环境里拉起来的进程，会被系统收走，Start-Process、wscript、schtasks 我都试过，都活不下来。

第九步：几个最值得记住的坑

前面说的那些之外，还有几个坑我印象特别深，每个都够你查半天。

一是 64 位下用 ctypes 不显式设返回类型，句柄会被截断。GetClipboardData 返回的 64 位句柄被当成 32 位的整数，剪贴板永远读出来是空字符串——我一度还误判成 Ctrl+F 唤起搜索失败了，其实快捷键一直好好的。教训就是，64 位 Windows 上，任何返回指针或者句柄的 Win32 函数，都得显式设好返回类型。

二是 BitBlt 截 Flutter 窗口只能拿到过期帧，这个前面第四步说了。

三是最小化等于画面冻住。我专门做了个对照实验，发消息之后盯着看了七十秒，画面指纹一动不动；把窗口挪出屏幕也一样，挪回来才立刻恢复。企微最小化的时候就不渲染了，这是操作系统加 Flutter 的硬行为，绕不过去。

四是 GetWindowRect 在最小化的时候不一定是负三万两千那样的坐标，微信最小化返回的是 314 乘 50 的小矩形。所以要用 IsIconic 判断，再用 GetWindowPlacement 拿还原矩形的位置。

五是企微有好几个标题都叫"企业微信"的窗口，不判断现在停在哪一页，就会把工作台的"审批""打卡"当成消息，生成一堆垃圾待办。

六是 @所有人被当成 @我，这个第五步说了。

七是"无需回复"被误判成待办，也是第五步的事。

八是改了代码，结果进程里跑的还是旧版本——把 pycache 删了再重启，别对着旧代码调半天。

最后：做到的和没做到的

做到的部分（前提是企微窗口得看得见）：

  • 打开企微，小组件自动弹出来；关掉，它自动退。
  • 自动抓新消息，AI 判断，钉到桌面，一键勾掉，顺便清掉角标。
  • 一个会话一张卡，按时间排，两级勾掉，群消息只收 @我的。

没做到的（这些是客观限制，不是代码问题）：

  • 企微最小化、挪出屏幕、或者停在工作台页的时候，读不到。你要是想眼不见为净，用别的窗口盖住它，或者扔到另一个虚拟桌面，这两种它照样读。
  • 用官方接口读聊天记录（公司没开会话内容存档）。
  • 读个人微信消息（官方没这接口）。

唯一能根治"只要登录就能读到"这条路，是让你们公司管理员去开通"会话内容存档"，这是个付费功能。开通之后服务端直接拿聊天记录，跟窗口状态完全没关系。读取的模块我已经提前写好了，公司一开通就能用。

完整源码和更细的踩坑记录都放在 GitHub 上了，仓库地址是 https://github.com/qinguobin/wecom-desktop-alert ，里面的 README 是功能清单加安装配置，PITFALLS 是三十四个坑，每个都写了症状、根因、解法。
